# Подготовка к экзаменам ЦУ — система и архитектура

Сборник сайтов подготовки к коллоквиумам и контрольным. Все экзамены устроены по одной схеме:
справочник → карточки → доказательства по шагам → банк задач → пробник с таймером, прогресс у каждого свой.
Сайт: https://chsa13.github.io/exams/

## А. Общая схема

### А.1 Экзамен = конфиг + контент

Каждый экзамен — папка `content/<id>/` и объект `Exam` (`src/content/schema.ts`):

| Поле | Что это |
|---|---|
| `id` | часть адреса: `/<id>/cards` |
| `subject`, `kind`, `short`, `icon` | предмет, «Коллоквиум» / «Контрольная работа 2», название для шапки, значок |
| `dates`, `when`, `format`, `scope` | даты (для обратного отсчёта на главной), формат и что входит — по-человечески |
| `levels` | есть ли продвинутый уровень (переключатель 🔴 / 🔴+⚫) |
| `features` | какие разделы показывать: `topics`, `cards`, `proofs`, `quant`, `tasks`, `mock` |
| `mock` | пробник: `ticket` (билет коллоквиума: подготовка + ответ по таймеру; `layout` — состав билета, без него — демо-билет матана; в `layout` можно задать `proofPoints` — разные баллы за теоремы, `theoryGate` — допуск к доказательствам, `scoreCap` — потолок оценки) или `test` (контрольная: позиции-слоты, по задаче из банка на каждую) |
| `sourceLabel` | подпись к номеру темы в справочнике («Лонгрид» по умолчанию, «Конспект, гл.») |
| `statementQuestions` | `false` — в билете нет вопросов «только формулировка»: у теорем нет отдельной грани «формулировка», карточка «сформулируй и докажи» оценивается один раз |
| `tasksNote`, `how` | текст над банком задач и страница «Как устроено» (Markdown) |
| `topics`, `tasks` | база знаний и банк задач |

Темы → единицы (`Unit`) с гранями «определение / формулировка / доказательство» (у каждой грани свой уровень),
доказательства разбиты на шаги, леммы — отдельные единицы в `lemmas`. Задачи — с подсказками и решением.

### А.2 Как добавить экзамен

1. `content/<id>/`: темы (`*.ts`, тексты — шаблонные строки md (Markdown + `$LaTeX$`)), `tasks.ts`, `how.ts`, `index.ts` с `Exam`.
2. Добавить его в `content/index.ts`.
3. `npm test` — общие проверки прогоняются для всех экзаменов: уникальные id, ссылки `uses`/`lemmas`, все формулы рендерятся KaTeX,
   у каждой единицы есть типичные ошибки, слоты пробной КР обеспечены задачами. Специфичные проверки — отдельным `describe`.
4. Исходники курса (PDF) — только во временной папке вне репозитория, см. правила контента.

### А.3 Архитектура

```
Vite + React + TypeScript   — SPA, BrowserRouter с base /exams/: / — список экзаменов, /<id>/… — раздел экзамена. Для GitHub Pages сборка кладёт копию index.html на каждый адрес и 404.html (vite.config.ts); старые ссылки с #/ переадресуются (main.tsx). Ссылки в текстах — от корня сайта: [Карточки](/<id>/cards)
KaTeX + marked              — формулы и Markdown
content/<id>/*.ts           — контент, типизирован схемой src/content/schema.ts
localStorage                — прогресс, отдельно на экзамен (экспорт/импорт JSON)
GitHub Pages                — деплой из main (.github/workflows/pages.yml), сначала тесты
```

```
content/
  index.ts                  # список экзаменов
  matan-colloc/             # коллоквиум по матану
  mia-colloc/               # коллоквиум по МИА («синий» матан)
  pilot-colloc/             # коллоквиум пилотного потока («чёрный» матан)
  linal-kr2/                # КР2 по линалу
src/
  content/schema.ts         # типы: Exam, Topic, Unit, Task, MockSpec
  exam.tsx                  # контекст текущего экзамена: useCat(), usePath()
  engine/catalog.ts         # Catalog: грани, индексы, видимость по уровню, очередь «что учить»
  engine/ticket.ts          # пробники: билет коллоквиума и контрольная по слотам
  engine/quant.ts           # генератор задач на кванторы (матан)
  store/progress.ts         # ProgressStore на экзамен; ключи localStorage — storageKey()
  pages/                    # HubPage (список экзаменов) + страницы раздела экзамена
tests/                      # контент, движок, исходники
```

Ключи localStorage: `exams:<id>:<progress|cards|mock>:v1`.

Статистика — Umami Cloud (`src/analytics.ts`, скрипт в `index.html`), без cookies. Просмотры страниц шлём вручную при смене маршрута, события: `mock-start`, `mock-finish` (exam, percent) и `activity` — сводка раз в 5 минут и при уходе со страницы (exam, theory — оценённые карточки и доказательства, tasks — открытые решения). На localhost не работает (`data-domains`).

У коллоквиума по матану оставлены старые ключи
(`colloc-matan-v1` и т.д.) — сайт переехал с `/colloc` на `/exams`, но домен тот же, и прогресс сохранился.

### Б.2 Система подготовки

#### 2.1 База знаний: атомарные «единицы»

Единица = один пункт из списка вопросов (например, «Теорема о зажатой последовательности»).
У неё до трёх «граней», и **у каждой грани свой уровень**:

- **Определение / формулировка** — точный текст + запись в кванторах.
- **Доказательство** — разбито на шаги (5–10), у каждого шага короткое название («выбираем N = max(N₁, N₂)»).
- **Опора**: одна строка «идея», типичные ошибки, на какие единицы ссылается (лемма 1 → Больцано–Вейерштрасс), ссылка на лонгрид.

Пример: «Теорема об обратной функции» — формулировка 🔴, доказательство ⚫.
Поэтому фильтр уровня работает по граням, а не по темам.

#### 2.2 Типы заданий (тренажёры)

| Режим | Что делает | Проверка |
|---|---|---|
| **Карточки** (опр./формулировки) | Название → вспомни → открой ответ | Самооценка: «не знаю / частично / знаю» |
| **Кванторы** | «Запиши lim_{x→3−0} f(x) = −∞ в кванторах»; отрицание определений | Автогенератор: тип точки (a, a±0, ±∞, ∞) × тип предела (A, ±∞, ∞) × (функция / последовательность). Сверка с эталоном + собрать запись из блоков |
| **Доказательство по шагам** | Шаги открываются по одному; режимы «расставь шаги по порядку» и «что пропущено?» | Порядок — автоматически; содержание — самооценка по шагам |
| **Верно / неверно** | «Всякая ли ограниченная последовательность сходится?» | Ответ да/нет + обязательный контрпример/аргумент, затем эталон |
| **Задачи** | Дирихле, стандартные пределы (aⁿ/n!, n^k/aⁿ, ⁿ√n, ⁿ√a, logₐn/n), задачи из контрольных | Подсказки уровнями (идея → план → решение) |
| **Пробный билет** | Генерация билета по структуре демо, таймер 45 мин | Затем фаза «ответа»: открываем эталоны, отмечаем баллы по критериям → итог из 11 |

#### 2.3 Повторение и прогресс

- У каждой грани статус: `new → weak → shaky → known`. До коллоквиума считанные дни, поэтому вместо долгих интервальных схем — очередь «сначала слабое, потом давно не виденное».
- **Карта готовности**: таблица «тема × (опр / форм / док)» с цветом, плюс прогноз баллов по красному.
- Кнопка «Режим последнего вечера»: только то, что ещё `weak/shaky`, плюс все формулировки из доказательств.

#### 2.4 Уровень (основной / + продвинутый)

- Переключатель в шапке: **🔴 Основной** / **🔴+⚫ Основной + продвинутый**. Хранится в браузере.
- 🔴: ⚫-грани скрыты, в пробном билете вопросы 7, 10, 14 заменяются на 🔴 или показаны серыми с пометкой «не идёт в зачёт».
- 🔴+⚫: всё видно, у каждого вопроса значок уровня, счёт по двум шкалам отдельно.

#### 2.5 Справочник

Весь материал по темам с поиском — как удобный сборник, ссылки «где в лонгриде».
Плюс страница «Как отвечать»: регламент, распределение 45 минут, что проверяет экзаменатор.

### Б.3 Наполнение контентом

1. Каркас из списка вопросов → `topics.yaml` + пустые единицы с уровнями по граням.
2. Тексты из «основного уровня» и «Сборника», сверка с лонгридами; формулы в LaTeX.
3. Доказательства разбиваются на шаги вручную (это основная ценность сайта).
4. Задачи: демо-билет, упражнения лонгридов, контрольные 2025 (основной уровень).
5. Проверка: сборка падает, если у единицы нет уровня или битая формула.

### Б.4 План работ (с учётом сроков)

| Этап | Что | Результат |
|---|---|---|
| **MVP** | Справочник + карточки + переключатель уровня + все 🔴 единицы | Уже можно учить |
| 2 | Доказательства по шагам + пробный билет с таймером | Репетиция коллоквиума |
| 3 | Тренажёр кванторов + задачи | Блок «Задачи» билета |
| 4 | ⚫ контент, карта готовности, экспорт прогресса | Для продвинутых |

  затем самопроверка по баллам задачи (за ответ без «почему» — не больше половины).
- Все числовые ответы проверены sympy.

## Д. Коллоквиум пилотного потока (полностью «чёрный» матан)

ЦУ, 2026/27, 1 семестр, лектор В. Лопаткин. 18 ноября, подготовка ~45 минут, без материалов.

Источники: список вопросов «Коллоквиум 1» (каркас: 42 вопроса по теории и 40 теорем) и конспект «The Hitchhiker's Guide to the Calculus Galaxy» (342 с.; лекции — главы 1, 2, 4, семинары — 5–9). Формат билета — из сообщений лектора в чате потока.

- Билет: 5 вопросов по теории по 0,5 и 4 теоремы — 1,5, 2, 2, 2,5 (формулировка и доказательство одним пунктом). Чтобы перейти к теоремам, нужно сдать не меньше 4 вопросов из 5. Итого 10,5 балла, оценка — максимум 10.
- В пробнике теорема с более длинным доказательством (шаги вместе с леммами) получает больший вес — наше предположение.
- Один уровень (`levels: false`), звёздочка чёрная. Банка задач нет: в билете задач нет (`features` без `tasks`).
- Отдельных вопросов «только формулировка» нет (`statementQuestions: false`): формулировка теоремы спрашивается только вместе с доказательством. Итого 83 вопроса: 42 по теории и 41 доказательство (40 теорем + лемма).
- Вопрос по теории = единица с гранью «определение»: текст отвечает на все подвопросы пункта. Теорема = формулировка + доказательство по шагам; ссылки на другие теоремы списка — `uses`, вспомогательная лемма (nₖ ≥ k) — `lemmas`.
- Определения — как в курсе: предел функции — непрерывное доопределение в точке прикосновения, окрестности открыты в относительной топологии, замкнутое = содержит все точки прикосновения. В O-символике — порядок кванторов из списка вопросов (∃C ∃N), в конспекте там опечатка.

## Е. Правила контента (авторское право)

Репозиторий публичный, поэтому:
- **Не кладём файлы курса**: PDF лонгридов, сборников, контрольных, их текстовые выгрузки и скриншоты. Они только во временной папке вне проекта (`.gitignore` блокирует `*.pdf`, `*.txt`).
- **Пишем своими словами.** Определения и формулировки — математические факты, их можно излагать, но не копировать абзацами. Доказательства пересказываем своей разбивкой на шаги. Условия задач из контрольных переформулируем и меняем числа.
- В поле `source` указываем только ссылку вида «Лонгрид 10, теорема 2», без цитат.
